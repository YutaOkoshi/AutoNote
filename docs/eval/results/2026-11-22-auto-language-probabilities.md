# 確定版・自動の言語判定の確率（塊ごと）

- 日付: 2026-11-22。§1〜§3 はモデル ggml-large-v3-turbo-q5_0、§4 はアプリの確定版の既定モデル ggml-large-v3-turbo（量子化なし。`EngineCatalog.defaults` の batch）。塊の切り方は `LanguageRunPlanner`（0.5 秒以上の無音、発話 6 秒ごと。発話 2 秒未満の塊は判定しない）で、今の実装と同じ。
- 測り方: 塊ごとの `detectLanguage`（whisper の言語判定。全言語の softmax のうちの ja と en の確率）を一時的なログで書き出した（§1〜§3 は feature/auto-jaen の 09582f6、§4 は 85f4802 にログを足したビルド。ログはコミットしていない）。時刻は**窓（10 分）の中の秒**。
- 「確率」は whisper の全言語の中の確率、「割合」は ja と en の 2 つの中の割合（`LanguageGuess.japaneseShare`）。
- この結果は `LanguageRunPlanner.Config` の `switchShare`・`switchProbability`（どちらも 0.8）の根拠。

## 3. 閾値 0.8 にした理由と、受け入れた取りこぼし

- 相づちの誤判定は確率 **0.14〜0.76**（量子化なしのモデルでは 0.15〜0.73、§4）、本物の切り替えは日米 2017 で **0.76〜1.0**（取りこぼす 1 か所以外は 0.92 以上）、合成の混在で **0.53〜1.0**。両者は重なっていて、どの閾値でも両方を完全には分けられない。
- 0.8 は、観測した相づちの誤判定（q5_0 で最大 0.76、量子化なしで最大 0.73）をすべて止める最も低い値の近く（余裕 0.04〜0.07）。測ったのは IngCrowd の 2 会話・4 トラックで、ほかの会議で 0.8 を超える相づちの塊が出ないことまでは示していない。
- 受け入れた取りこぼし: 確率が 0.8 に届かない切り替え（合成の混在で q5_0 は 4 区間、量子化なしは 4 区間、日米 2017 で 1 か所）は、直前の言語のまま起こされる。合成の混在で確定版・自動の英語の残存が 80.2% → 61.6% に下がった（main は全体を英語で起こしていたので英語は残り、日本語は CER 89.8% で崩れていた）のはこのため。
- そうした理由: 誤った切り替えは**単一言語の会議の話者別トラック**（AutoNote の録音は自分 / 相手の 2 トラックで、相手のトラックは相づちが多い）という、よくある場面で起き、区間ごと別の言語で起こすので崩れ方が大きい（IngCrowd 05 自分 +3.2 ポイント）。取りこぼしは日英が交代する会議で、whisper 自身が迷う塊でだけ起き、次の確かな塊で切り替わる。迷う塊は whisper が固定の言語でも原語のまま出すことがある（日米 2017 の 965–1002 秒）。
- 見直すとき: 閾値を下げると合成の混在の英語は戻るが、相づちの誤判定（0.71・0.76）も切り替わる。トラックの相づちを別の方法で見分けられるようになれば下げられる。

### 結論

- 相づちの誤判定は 0.8 を超えず、合成の混在も日米 2017 も main より良くなったので、閾値 0.8（割合・確率とも）は既定のモデルでも合っている。コードは変えない。
