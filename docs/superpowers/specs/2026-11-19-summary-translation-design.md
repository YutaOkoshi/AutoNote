# 要約の翻訳（設計）

2026-11-19。v0.6.0 の文字起こしの翻訳（`2026-11-14-transcript-translation-design.md`）の続き。

## 目的と理由

日本語と英語が混ざる会議で、要約を読みたい言語で読めるようにする。ただし要約そのものは必ず原文（文字起こしの言語）で作り、できた要約を後から訳す。訳文から要約を作ったり、要約を最初から別の言語で書かせたりしない。原文の要約が正で、訳はその写しという関係を、録音中のライブ要約でも録音後の議事録でも同じにする。

## 利用者が決めたこと

- 要約は必ず原文どおりに作る。その後に翻訳する。ライブ要約でも録音後の議事録でも同じ。
- 文字起こしの訳文の見た目は今のまま（原文を小さく、その下に訳文を本文サイズ）。

## ゴール

- ライブ要約と議事録を、会議の言語で作る。
- 翻訳が有効なとき、できた要約を設定の翻訳先へ訳し、原文の下に訳文を並べて見せる。
- 原文の要約（`live-summary.json`、`minutes.json`）は書き換えない。

## 非ゴール

- 日本語・英語以外の言語。
- 訳文の編集。
- 文字起こしの訳文の見た目の変更。

## アンチゴール

- 訳文を要約の入力にすること。
- 翻訳のために録音やライブ文字起こしを遅らせること。
- 翻訳のために外部へ送る内容が増えること（翻訳は端末内のモデルで行う）。
- 既存の保存データ（`translation.json`、`live-translation.json`、`live-summary.json`、`minutes.json`）が読めなくなること。

## 現状（v0.6.0）

- ライブ要約の入力は原文の確定発話。出力言語はプロンプトの「発話と同じ言語で書く」だけで、混在だと揺れる（`Minutes/DefaultPrompt.swift:90`）。
- 議事録は「日本語で書く」固定（`DefaultPrompt.swift:8`）。英語の会議でも日本語になる。`SummaryInput.language` は使われていない。
- 翻訳は発話単位だけ。翻訳先は `translation_target`（auto / ja / en）、言語は ja と en の 2 つ。

## 方式（検討した 3 案）

1. **端末内の翻訳モデル（PLaMo）で要約を後から訳す（採用）**。原文の要約が残り、外部送信が増えない。利用者の指示どおり。要約の更新のたびに翻訳が走るので、訳文は数秒遅れて出る。
2. 要約を作る Claude に指定言語で書かせる。速いが、原文の要約が残らない。利用者の指示に反する。
3. 要約を作る Claude に原文と訳文の両方を出させる。1 回で済むが、訳が要約と一緒に作られるので「原文の要約が正」という関係が崩れ、外部の利用枠も増える。

## 設計

### 要約の言語

- 会議ごとに要約の言語を 1 つ決める。文字起こしの発話を文字数で数え、かな・漢字を含む発話が多ければ日本語、そうでなければ英語（既存の `TranslationLanguageDetector` の判定を流用）。ライブ要約は、その時点までの確定発話で決め、途中で変わったら次の更新から切り替える。
- プロンプトには「発話と同じ言語で」ではなく、決めた言語を名指しで渡す。指定は利用者が編集できる `prompt.md` の外側（アプリが付ける行）に置き、編集済みのプロンプトでも効くようにする。既定のプロンプトの「日本語で書く」は外し、`PromptMigration` で既定のままの利用者を移行する。

### 翻訳先

- 既存の `translation_target` を共有する。ja / en はその言語へ。auto は要約の言語の反対へ。翻訳先が要約の言語と同じなら訳さない。

### いつ訳すか

- 録音後: 翻訳が走る条件（`translation_mode` が off 以外で自動、または「翻訳する」ボタン）で、文字起こしに続けて議事録も訳す。議事録が後からできた場合や作り直された場合は、そのときに訳す。
- 録音中: `translation_mode` が during_recording のとき、ライブ要約が更新されるたびに、変わった項目だけを訳す。発話の翻訳より優先度を低くし、追いつかないときは古い要約の翻訳を捨てて最新だけを訳す。

### 訳す対象

- ライブ要約: now、decisions、todos の本文。
- 議事録: タイトル、要約、決定事項、次のアクション、要点、質問、リスク、期限などの本文。担当者名、日付、時刻、図（Mermaid）のノード名は訳さない。

### 保存

- 新しいファイル `live-summary-translation.json` と `minutes-translation.json` を `transcripts/<id>/` に置く。項目ごとに原文のハッシュと訳文を持ち、原文が変わった項目だけ訳し直す。既存ファイルの形式は変えない。

### 表示

- ライブ要約のペインと議事録の表示で、各項目の原文の下に訳文を置く。見た目と「訳文」スイッチは文字起こしと同じものを使う。訳がまだ無い項目は原文だけ。
- Vault のノート（Markdown）には、訳があるとき末尾に訳文の節を足す。訳は議事録より後にできるので、訳が完了した時点でノートを書き直す。利用者が手で編集したノートの扱いは既存の書き直しの規則に従う。

### 文言

- 「議事録は今までどおり原文から作ります」の注記（`TranslationPresentation.swift:147-148`）と設定の説明を、要約も訳すことに合わせて直す。外部送信の説明は変わらない（翻訳は端末内）。`PrivacyCopyTests` を合わせる。

## 作り手に任せること

要約向けの翻訳関数の形（発話向けの `UtteranceTranslator` とは履歴の扱いが違う）、翻訳モデルを発話の翻訳と取り合わない仕組み、ハッシュと保存の細部、訳文の節の Markdown の形、テストの分け方。

## Lead が置いた判断（利用者の明示の指示ではないもの）

- 要約の言語は、会議の発話の多数派で決める。
- 翻訳先は既存の設定を共有し、要約専用の設定を増やさない。
- Vault のノートに訳文の節を足す。
- 録音中の要約の翻訳は、`translation_mode` が during_recording のときだけ。
