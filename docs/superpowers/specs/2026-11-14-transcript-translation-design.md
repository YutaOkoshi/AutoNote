# 文字起こしを端末内で翻訳する（PLaMo 3 Translate） — 設計

日付: 2026-11-14　対象: `feature/live-summary-side-pane`（d940d4e、v0.5.0）以降。事前調査は [PLaMo 3 Translate 組み込みの事前調査](../research/2026-11-14-plamo-3-translate-spike.md)（以下「調査メモ」）。

## 意図

利用者の言葉（2026-11-14）: 「PLaMo 3 Translate の 4 モデルも使えるようにしてほしい」「文字起こしの後に翻訳する」。英語の会議を日本語で、日本語の会議を英語で読めるようにする。翻訳は Claude に送らず、端末の中だけで行う。

利用者が決めたこと:
- 訳すタイミングは **録音中も録音後も** 用意し、設定で選べる。
- 訳文は **文字起こしの各行に併記** する。併記するときは **原文を小さく** して、1 画面に少しでも多くの行が入るようにする。
- 訳す向きは **日英を自動で反転**（日本語の発話は英語へ、英語の発話は日本語へ）。

## ゴール

- 設定で翻訳をオンにし、モデルをダウンロードすれば、文字起こしの各行に訳文が付く。
- 録音後: 確定版の文字起こし全体を訳し、会議に保存する。1 時間の会議を 2B（Apple Silicon）で数分。
- 録音中（任意）: ライブ文字起こしの確定した行を順に訳し、録音中の画面に併記する。停止後は確定版の訳で置き換える。
- 過去の会議・取り込んだ会議も、会議の画面から「翻訳する」で訳せる。

## 非ゴール

- 日本語・英語以外への翻訳 UI（モデルは 53 言語に対応するが、最初は訳す先を 自動／日本語／英語 に限る）。
- 議事録（minutes.json、Vault のノート）や Claude に渡す入力を訳文にすること。議事録づくりは今までどおり原文から。
- 訳文の書き出し（コピー・Markdown・Vault）。後で足す。
- 言い淀みや Whisper の幻覚を訳す前に取り除く処理。
- 31B モデル。
- MLX での推論。

## アンチゴール（できても失敗）

- 翻訳のために文字起こしや訳文が端末の外に出る（通信してよいのはモデルのダウンロードだけ）。
- 翻訳が、録音・ライブ文字起こし・確定版の文字起こし・議事録づくりを遅らせる・止める・失敗させる。翻訳の失敗で会議が「失敗」の状態になる。
- 原文の文字起こし（transcript.json / transcript.md）が書き換わる。
- ggml を共有にしたことで、Whisper の認識精度（CER）や速度が落ちる。
- ライセンスへの同意と業務利用の事前登録の案内を見せずに、モデルを使える状態になる。

## 画面

文字起こしの行（録音中の左ペインと、完了した会議の「文字起こし」タブ）。訳文があり、表示がオンのとき:

```
00:12:03 相手  We moved about sixty percent of the tenants over the weekend.   ← 原文: 小さく（caption 程度）、二次色
               テナントの約 6 割を週末に移行しました。                          ← 訳文: 今の本文の大きさ
00:12:09 自分  残りも今月末までにいけそうですか。
               Are we on track to finish the rest by the end of the month?
```

- 時刻と話者は今までどおり行頭。原文と訳文の 2 行で 1 発話。行間は今より詰め、1 画面に入る発話数を今の 1 行表示より大きく減らさない。
- 文字起こしの見出し行の右側に「訳文」の切り替え（オン/オフ）。オフなら今の表示（原文を今の大きさで 1 行）に戻る。会議ごとではなくアプリ全体で覚える。
- 訳がまだ無い行は原文だけを今の大きさで出す（訳を待つ間に行の高さが揺れすぎないこと）。
- 原文と訳す先の言語が同じ行（固定モードで日本語→日本語など）は訳さず原文だけ。

## 決めたこと

1. **設定**（設定画面に「翻訳」の欄。置き場所は作り手に任せる）
   - 翻訳: オフ（既定）／録音後に訳す／録音中も訳す（録音後も訳す）。
   - 訳す先: 自動（日↔英、既定）／日本語／英語。
   - モデル: 0.8B／2B／8B。既定は機械で決める: Apple Silicon かつメモリ 16 GB 以上 → 2B、それ以外（Intel・8 GB 機）→ 0.8B。8B は選べるが、メモリ 16 GB 未満では選べない（理由を添えて無効）。
   - 「録音中も訳す」は Apple Silicon だけ。Intel では選べない（理由を添えて無効）。
   - モデルのダウンロード・削除・サイズ表示は Whisper のモデルと同じ作法。
2. **モデルの取得とライセンス**
   - PFN 公式の Hugging Face リポジトリの GGUF（Q4_K_M）を、リビジョンと sha256 で固定して取得する（調査メモ: PFN は公開後に GGUF を差し替えている）。自前で量子化・再配布しない。モデルはアプリに同梱しない。
   - 初回のダウンロードの前に、PLaMo Community License への同意を求める。表示: ライセンス本文へのリンク、「業務（社内利用を含む）で使う場合は PFN への事前登録が必要。直近の売上 10 億円以下は無料、超える場合は別途契約」と登録フォームへのリンク、「Built with PLaMo」。同意は設定に保存し、同意しない限りダウンロードしない。
   - 設定の翻訳の欄と README に「Built with PLaMo」とライセンスへのリンクを置く。
3. **推論手段**: llama.cpp を同じプロセスで使う。whisper.cpp と llama.cpp を同じ ggml（PLaMo 3 の YaRN の修正を含む 2026-11-05 以降の版）でビルドし、1 つの xcframework（または ggml を共有する複数の xcframework）にまとめる。`scripts/build-whisper-xcframework.sh` と `release.yml` を更新する。x86_64（AVX2/FMA/F16C）も今と同じく含める。これが組めない場合だけ、`llama-server` を補助プロセスとして同梱する案に退く（退く前に Lead に相談）。
4. **プロンプト**: PFML3 を直接組み立てる（調査メモ 1 節）。各発話に直前 3 組の原文と訳を履歴として付ける。日本語へ訳すときは `form=polite`。停止文字列は `<|plamo:tag|>` と `<|plamo:bos|>`。貪欲法。1 発話の出力上限を設ける（暴走防止）。
5. **言語の判定（自動のとき）**: 発話ごとに文字種で決める。仮名か漢字を含めば日本語 → 英語へ、それ以外 → 日本語へ。数字・記号だけの発話は訳さない。
6. **録音後の翻訳**: 確定版の文字起こしができた後、議事録づくりとは独立に走る後処理。議事録づくりを待たせない・待たない。失敗しても会議の状態は変えず、会議の画面に「翻訳できませんでした」と再試行を出す。進捗（n / 全数）を会議の画面に出す。アプリを終了したら中断し、次回は「翻訳する」で再開できればよい（途中から再開は作り手に任せる）。
7. **録音中の翻訳**: ライブ文字起こしで確定（`isFinal`）した行だけを順に訳す。翻訳は録音・ライブ文字起こしより低い優先度で、遅れたら古い行を飛ばして最新に追いつく（飛ばした行は原文のまま。停止後の確定版の訳で埋まる）。録音を始めたときにモデルを読み込み、停止したら解放する。
8. **保存**: 会議のフォルダに `translation.json`（確定版の訳。モデル名・リビジョン・訳す先・作成時刻・原文と対応づけるキー・訳文）と、録音中だけ `live-translation.json`。確定版の訳ができたら `live-translation.json` は消す。原文が後で変わった（文字起こしをやり直した）ときは、古い訳を出さずに「訳し直す」を出す。対応づけのやり方は作り手に任せる。
9. **会議の画面**: 完了した会議（と処理中の会議）で、訳文が無く翻訳が使える状態なら「翻訳する」、訳文があれば「訳し直す」。翻訳がオフでも、モデルがあれば手で訳せる。
10. **メモリの扱い**: モデルは使うときだけ読み込み、録音後の翻訳が終わったら解放する。終了やモデル切り替えのときに llama と whisper のコンテキストを決まった順に解放する（調査メモ 2.2 節: 解放しないと終了時に Metal の assert で落ちる）。
11. **CLI と E2E**: `autonote dev translate` を足す。入力の文字起こし（JSON）と訳す先を受け、偽の翻訳器で決定的に訳した結果を 1 行の JSON で出す（本物のモデルがあるときは `--model <path>` で本物も使える）。E2E は偽の翻訳器で出力の形と言語の判定を固定する。本物のモデルを使うテストはモデルがあるときだけ走る（無ければ SKIP）。

## 制約

- 版（`Info.plist`、`AutoNoteVersion.swift`）は上げない。`git push`、PR の作成、main への変更はしない。
- 実録音・マイク・本物の `claude` の呼び出しが要る確認はしない。
- このマシンは Xcode なし（Command Line Tools のみ）。ビルド・テストの回避策は `.scratch/env.sh` 相当（調査メモ「測定環境」と、Lead が渡すメモを参照）。
- 秘密情報（トークンなど）は 1Password に置く方針。Hugging Face のトークンが要るなら作らずに止めて報告する。

## 作り方の案と選んだもの

- 推論: llama.cpp 同一プロセス（選択）／llama-server 補助プロセス（退路）／MLX（Swift 側の対応が無く Intel で動かないので不採用）。
- 録音中の訳の置き換え: 確定版の訳で丸ごと置き換える（選択）。ライブの訳を確定版に引き継ぐのは、行の対応が崩れるので採らない。

## 作り手に任せること

- 設定画面での置き場所と文言、ダウンロードの UI の細部。
- `translation.json` の対応づけのキーと形式、途中からの再開。
- xcframework を 1 つにするか、ggml を共有する複数にするか。
- 発話をまとめて訳す（バッチ）かどうか。
