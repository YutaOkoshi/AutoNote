# 録音中の要約を右ペインに置き、「聞きたいこと」を足す — 設計

日付: 2026-11-14　対象: main（HEAD 4473211、v0.4.1）以降。[録音中のリアルタイム要約の設計](2026-10-28-live-summary-design.md)の表示（5）と入出力（1）を置き換える。それ以外（周期・失敗の扱い・呼び方・設定）は変えない。

## 意図

利用者の言葉（2026-11-12〜14）: 「MTG 中のリアルタイム要約がみにくい。MeetNote を参考にしてほしい」。会議中にあの要約で知りたいのは次の 3 つ。

1. 会議の途中で、**いま話しているトピックは何か**
2. 会議の最後で、**お互いの宿題は何か**
3. **自分が聞きたいことを全て聞けているか**

今のカードは文字起こしの上に 220pt までで置かれ、決定事項の箇条書きが 10 件以上並んで、宿題はスクロールしないと見えない。宿題に自分と相手の区別がない。3 は仕組みがない。

## ゴール

- 録音中、文字起こし（左）と要約（右）が左右に並び、要約は縦いっぱいを使う。
- 要約は上から「いまの話題」「聞きたいこと」「宿題（自分／相手）」「決定事項」。上の 3 つは既定で開き、決定事項は既定で閉じる（件数だけ見える）。
- 利用者が「聞きたいこと」を録音前にも会議中にも書き足せる。要約の更新のたびに、聞けたかどうかを Claude が文字起こしから判定してチェックを付ける。手でも付け外しできる。
- 停止後も、議事録ができるまでは同じ内容（聞けていない項目を含む）が読める。

## 非ゴール

- 文字起こしを吹き出しにすること（時刻・話者・発話の行のまま。話者が宿題の読み取りに効く）。
- MeetNote の「チャット」「文字修正」タブ、「概要」の文章、話題ごとの重要ポイント。
- 聞きたいことを他のアプリ・カレンダーの説明欄から取り込むこと。
- 聞きたいこと・宿題の分類を最終の議事録（minutes.json、Vault のノート）に書くこと。
- 要約の周期・モデル・バックオフ・既定オフの変更。

## アンチゴール（できても失敗）

- 聞きたいことの編集やチェックの操作が、録音・ライブ文字起こしを遅らせる・止める。
- 要約の更新が、利用者が手で付け外ししたチェックや、更新の呼び出し中に書き足した項目を消す・巻き戻す。
- モデルが聞きたいことの文言を書き換える・項目を増減させる（項目は利用者のもの。モデルが返すのは id ごとの判定だけ）。
- 一度「聞けた」になった項目が、次の更新で勝手に「未」に戻る。
- リアルタイム要約がオフのときに、聞きたいことのテキストが Claude に送られる。

## 決めたこと

1. **配置。** `RecordingDetailView` の帯とボタン行の下を左右 2 列にする。左が文字起こし、右が要約ペイン。右ペインの幅は詳細領域の約 45%（最小 320pt）。詳細領域の幅が 2 列に足りない（目安 720pt 未満）ときは上下に並べ、今と同じく要約を上・文字起こしを下にする（要約の高さは今の上限を保つ）。
2. **右ペインを出す条件。** リアルタイム要約がオン（`liveSummaryEnabled`）の録音では、**録音開始から**右ペインを出す（最初の結果を待たない。聞きたいことを書く場所だから）。結果がまだ無い節は薄く「（まだありません）」。オフの録音では右ペインを出さず、今の 1 列のまま。前の設計の「最初の結果が来るまでカードは出さない」はオンのときに限り取り消す。
3. **節と順序。** いまの話題（1 文、本文より一段大きい太字）→ 聞きたいこと（題の右に「聞けた数 / 全数」）→ 宿題 → 決定事項（題の右に件数）。開閉は節ごとに設定へ保存する（既定: 上 3 つ開、決定事項 閉）。既存の `live_summary_card_collapsed`（カード全体の折りたたみ）は廃止し、読み込み時は無視する。
4. **宿題の分け方。** `todos` の各項目に `side`（`self` / `other` / `unknown`）を足す。文字起こしの話者ラベル（自分／相手）から、その宿題を**引き受けた側**をモデルが決める。表示は「自分」「相手」「その他」の小見出しで分け、空の小見出しは出さない（3 つとも空なら「（なし）」）。`owner`（名前が出たとき）は今までどおり末尾に「— 担当」。古い `live-summary.json`（`side` なし）は `unknown` として読む。
5. **聞きたいことの持ち方。** 項目は `{id, text, asked, askedBy}`。`id` は追加時に振る短い一意の文字列。`askedBy` は `model` / `user` / nil で、利用者が手で付け外しした項目（`user`）はモデルの判定で上書きしない。保存先は `transcripts/<id>/questions.json`（`live-summary.json` の隣。要約の状態とは別ファイルにして、要約の書き込みと利用者の編集が互いを上書きしないようにする）。上限 30 件、1 件 200 文字。
6. **録音前に書く場所。** 録音していないときの画面（録音を始める画面）に同じ「聞きたいこと」の欄を置き、下書きとしてアプリのデータ置き場に保存する（`pending-questions.json`）。録音を始めたら下書きをその会議の `questions.json` に移し、下書きは空にする。リアルタイム要約がオフでも下書きと手動のチェックは使える（オフの録音では、聞きたいことの欄だけを文字起こしの上に小さく出す。Claude には送らない）。
7. **判定。** 要約の入力に、未確定（`asked == false` かつ `askedBy != user`）の項目だけを `{id, text}` で渡す。出力に `asked_question_ids: [String]` を足し、「今回までの発話で、その問いが話題に上がり答えが得られたもの」の id を返させる。受け取ったら、いまの `questions.json` を読み直して該当 id に `asked = true, askedBy = model` を付ける（呼び出し中に足された・消された・手で変えられた項目はそのまま）。知らない id は無視。プロンプトに「答えが出ていない・話題に触れただけなら含めない」「推測しない」を明記する。新しい発話が無いときは今までどおり呼ばない（聞きたいことを足しただけでは呼ばない。次の周期で渡る）。
8. **操作。** 追加: 欄の下の「＋ 聞きたいことを追加」で 1 行の入力欄、Return で確定して続けて次を書ける、空のまま Return か Esc で閉じる。チェック: 行頭を押して付け外し（`askedBy = user`）。削除: 行にポインタを置いたときの × と右クリックのメニュー。文言の編集はダブルクリック。いずれもキーボードと VoiceOver で操作できるラベルを付ける。
9. **停止後。** `ProcessingDetailView` と `MinutesMissingView` の読み取り専用カードは、同じ節の部品を縦に並べて使う（聞きたいことはチェックの付け外しだけ可、追加・削除は不可）。`CompletedDetailView` は今までどおり出さない。
10. **見た目。** 色は既存のアクセント色とシステムの二次色だけを使い、新しい色を足さない。ダークモードと「透明度を下げる」「コントラストを上げる」で読めること。
11. **CLI と E2E。** `autonote dev live-summary` に `--questions <json>` を足し、偽の要約器は決定的に（例: 先頭の未確定 1 件を聞けたにする）返す。E2E は出力の形（`side`、`asked_question_ids`）と、2 回目の呼び出しで聞けた項目が渡らないことを固定する。

## 制約

- `docs/development.md` の「開発の約束事」（Swift 6 strict concurrency、TDD、`AutoNoteCore` に表示の文言と判定を置き SwiftUI は薄く、E2E は `scripts/e2e-check.sh`）。
- 既存の `LiveSummaryScheduler` の周期・条件・バックオフ・停止時の最後の 1 回は変えない。
- `--json-schema` は `additionalProperties: false`。スキーマとプロンプト（`DefaultPrompt.liveInstructions`）とフィクスチャを同時に直す。
- 利用者ガイド（`docs/guide/`）のリアルタイム要約の説明と、一般タブの外部送信の説明文（聞きたいことのテキストも送る）を直す。

## 作り方の案と選んだもの

- **A. 既存のライブ要約を広げる（選択）。** 状態・スキーマ・プロンプトに `side` と聞きたいことの判定を足し、画面を 2 列に組み替える。呼び出しは今の 1 回のまま増えない（1 回あたり約 1 万トークンの固定費が増えない）。
- B. 聞きたいことの判定を別の Claude 呼び出しにする。責務は分かれるが、固定費が 2 倍になり、同時実行の制御も増える。選ばない。
- C. 見た目だけ直し、聞きたいことは手動のチェックリストにする。利用者の「全て聞けているか」を会議中に自分で管理させることになり、要望の 3 に届かない。選ばない。

## 作り手に任せること

- 型の名前と置き場所、`AppModel` への載せ方、`questions.json` の読み書きの直列化の方法。
- 2 列の実装（`HSplitView` か `HStack` + 固定比率か。利用者が境界を動かせるなら幅を保存してよい）。
- アイコン（SF Symbols）の選択、余白、角丸。上の図に近づける。
- 録音前の画面のどこに欄を置くか（その画面の既存の並びに合わせる）。
- `pending-questions.json` の置き場所（`AppPaths` に足す）。
