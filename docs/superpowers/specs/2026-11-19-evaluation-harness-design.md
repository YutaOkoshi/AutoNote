# 文字起こしと要約の評価の仕組み（設計）

2026-11-19。調査の根拠は作業用の `EVAL-RESEARCH.md`（未コミット）にある。

## 目的と理由

AutoNote の文字起こし（ライブ・確定版）と議事録要約の品質を、実在の会議音声で数字にする。きっかけは、日本語と英語を混ぜて話すとライブにロシア語の断片が出たこと、日本語固定だと英語の発話が落ちることが、利用者の実録音でしか分からなかったこと。変更の前後を同じ音声で比べ、良くなったか悪くなったかを言えるようにする。

## ゴール

- 公開されている本格的な会議音声を、1 コマンドで取得・文字起こし・採点できる。
- 2 つのビルド（例: main と修正ブランチ）の結果を並べて差を出せる。
- 利用者の手元だけにある録音（共有できない本業 PC の日英混在会議を含む）でも同じ採点が回り、共有してよい集計値だけを出せる。
- 要約を、正解の決定事項・アクションとの突き合わせと、Claude による採点で測れる。

## 非ゴール

- CI に載せること（音声が大きく、要約は外部呼び出しになる）。
- 話者分離（DER）の評価。AutoNote は「自分 / 相手」をトラックで分けるので、当面は本文だけを測る。
- 精度の絶対値を他の製品や公開ベンチマークと比べること。

## アンチゴール

- 音声・正解書き起こし・利用者の録音の本文を、リポジトリ・結果ファイル・ログに入れること。
- 取得元の規約に反する取得（YouTube からのダウンロードなど）。
- 採点のたびに黙って Claude を呼び、利用枠を消費すること（要約の採点は明示の指定があるときだけ。結果はキャッシュする）。

## 制約

- 追加の依存を入れない。採点と変換は Python 標準ライブラリのみ（既存の `scripts/cer.py` と同じ流儀）、音声変換は `ffmpeg`、文字起こしは既存の `autonote dev transcribe`。
- Xcode なしの環境で動く（`docs/development.md` の回避策）。
- データは git 管理外の `.eval-data/` に置く（`.gitignore` に足す）。

## 方式（検討した 3 案）

1. **`scripts/eval/` に Python とシェルで作る（採用）**。既存の `autonote dev transcribe` を外から回す。依存が増えず、採点規則を変えてもアプリを作り直さなくてよい。本業 PC にもスクリプトと実行ファイルだけ持っていける。
2. `autonote dev eval` として Swift で作る。アプリ内部の型を直接使えるが、採点規則を変えるたびにビルドが要り、XML や JSON の変換を Swift で書く量が多い。
3. 既製の評価ライブラリ（jiwer、sacrebleu など）を使う。指標は信頼できるが pip の依存が増え、日本語の正規化と整文済み議事録への合わせ込みは結局自前になる。

## データセット

`scripts/eval/datasets.json` に、取得元 URL、SHA-256、ライセンスと出典表示、切り出し範囲、言語、正解の変換方式を宣言する。

| 区分 | データ | 正解 | 状態 |
|---|---|---|---|
| 英語の会議 | AMI Meeting Corpus から 3 会議（ES・IS・TS 系を 1 つずつ。CC BY 4.0） | 語単位の書き起こし、人手の要約（abstract / actions / decisions / problems） | すぐ使える |
| 日本語の討議 | 党首討論 2010-04-21（Wikimedia Commons、CC BY 3.0、ライセンス審査は未了と表示） | 国会会議録（整文済み、時刻なし） | すぐ使える |
| 日英混在 | 日米共同記者会見 2017-02-10（Commons、CC BY 3.0） | 英語部分のみ（米国政府の記録） | すぐ使える |
| 日英混在（合成） | AMI と党首討論の正解つき区間を、発話の単位で交互につないだもの | つないだ区間の正解から自動で作る | 作る。件数を増やすための手段で、語中の切り替えは再現できない |
| 日本語の会議 | RWCP-SP01 | 未確認 | 利用者が申請中。届いたら宣言を足す |
| 手元の録音 | 利用者の録音と、利用者が直した書き起こし | 人手 | `.eval-data/private/` に置く。宣言は git 管理外の `datasets.local.json` |

MagicData の雑談は会議でなく、ライセンス表示が矛盾しているので採用しない。

## 文字起こしの指標

- 日本語は文字誤り率、英語は単語誤り率。素の値と、正規化後（記号・句読点・フィラー・数字表記）の値の 2 本を出し、正規化規則の版を結果に記録する。主指標は正規化後。
- 時刻のない正解（国会会議録）は、出力を正解の中の最も合う区間に合わせて採点する。
- 混在は全体の文字誤り率に加え、英語部分の単語誤り率を別に出す。
- ライブと確定版を同じ音声で並べる。
- 想定外の文字種（選んだ言語で出ないはずの文字）を含む発話の割合。
- 英語の残り方: 正解の英語の語のうち、出力に英語として現れた割合（言語を ja に固定したときと auto のとき）。
- 繰り返しの幻覚の件数、まとまった脱落（正解側で連続して欠けた長さ）。
- 処理時間（RTF）。

## 要約の指標

- AMI の正解の decisions・actions と、`MinutesOutput` の `decisions`・`next_actions` を 1 件ずつ対応づけ、再現率と適合率を出す。対応づけは Claude に判定させる。
- 忠実性: 要約の各項目に書き起こし上の根拠があるかを、固定の基準で Claude に採点させる。
- 入力は 2 通り: 正解の書き起こし（要約だけの力を見る）と、AutoNote の確定版の書き起こし（通しの力を見る）。
- 採点モデル、プロンプトの版、スキーマの版を結果に記録する。入力のハッシュで結果をキャッシュし、同じ入力では呼び直さない。
- そのために `autonote dev summarize` に `MinutesOutput` の JSON をファイルへ出す口を足す（製品コードの変更はこれだけ）。

## 実行と結果

- `scripts/eval/fetch.py`（取得と検証、参照の変換）、`run.py`（文字起こしの実行。`--autonote <実行ファイル>` と `--label <名前>` でビルドを切り替える）、`score.py`（採点）、`report.py`（表と、基準との差）。まとめて回す入口を 1 つ用意する。
- 結果は `docs/eval/results/<日付>-<label>.json` と `.md`。集計値だけを書き、本文は書かない。差分の例示が要るときは公開データに限る。
- 判定は基準との差で行う（絶対値は正解の作りの癖で動く）。基準は `docs/eval/baseline.json`。
- 手元の録音向けに、確定版の書き起こしを下書きとして書き出す補助と、直した書き起こしを正解として取り込む手順を `docs/eval/README.md` に書く。

## 作り手に任せること

AMI のどの会議を選ぶか、正規化規則の細部、合成の混在セットの作り方（区間の長さ、件数）、Claude への採点プロンプトの文面、スクリプトの分割。いずれも結果ファイルに版を残すこと。

## Lead が置いた判断（利用者の明示の指示ではないもの）

- スクリプトは Python 標準ライブラリのみ、置き場所は `scripts/eval/` と `docs/eval/`。
- MagicData を採用しない。
- 混在の件数不足は合成セットで補う。
- CI に載せない。
