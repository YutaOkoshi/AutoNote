# 録音中のリアルタイム要約 — 設計（計画 09 の種）

日付: 2026-10-28　対象: main（HEAD ebb228a、計画 07 まで）以降。計画 08（窓分割）とは独立。

## 意図

会議の最中に「今何の話をしているんだっけ？」と「始まってから何が決まり、誰に何の宿題が付いたか」を、録音ウィンドウの中で見られるようにする（利用者の要望、2026-10-28）。今はライブ文字起こしの行が流れるだけで、流れを掴み直す手段がない。

ライブ文字起こし（確定した発話）を 10〜30 秒ごとに Claude Code に渡し、**いまの話題 1 文**と**決定事項・宿題の累積リスト**を更新して表示する。更新の間隔は設定画面から変えられる。

## ゴール

- 録音中、右ペインの上部に「いま: 〈1 文〉」「決定事項」「宿題」が出て、設定した間隔で更新される。
- 1 回の更新に送る量が会議の長さに比例して増えない（前回の結果 + 新しい発話だけを送る）。
- Claude Code が無い・ログインしていない・利用制限中でも、録音とライブ文字起こしには一切影響しない。
- 停止後も、議事録ができるまでは最後の要約が見える。
- 設定: オン/オフ（既定オフ）、更新間隔（秒）、使うモデル。

## 非ゴール

- 要約を議事録に流用すること。最終の議事録は今までどおり確定版の文字起こしから作る（将来、決定事項リストをヒントとして渡す案は別計画）。
- メニューバーや通知に要約を出すこと。
- 話者ごとの要約、発言の引用、時間軸つきのタイムライン。
- Claude Code 以外の要約器。

## アンチゴール（できても失敗）

- 要約の呼び出しが録音やライブ文字起こしを遅らせる・止める（別 Task、別作業ディレクトリ、失敗は握りつぶしてログ 1 行）。
- 同じ会議で 2 つの要約呼び出しが同時に走る。
- 最終議事録の `ClaudeCodeSummarizer` と作業ディレクトリ（`paths.claudeWorkingDirectory`）を共有する（最終議事録は毎回そのディレクトリを空にする。前の会議の議事録が録音中に作られることがある）。
- 毎回 `claude auth status`（30 秒タイムアウト）を呼ぶ。20 秒間隔の中で 30 秒待てない。
- 音声を送る。送るのは確定した発話のテキストだけ。

## 決めたこと

1. **入力と出力。** 1 回の更新は「前回の状態（いまの 1 文・決定事項・宿題）」と「前回の成功以降に確定した発話（最低でも直近 120 秒の発話を含める）」を渡し、JSON で**状態の全体**を返させる: `now`（60 文字以内の 1 文。話がまだ無ければ空）、`decisions: [String]`、`todos: [{text, owner?}]`。リストはモデルが前回のものを引き継いで追加・統合する（重複は統合、取り消された決定は消す）。各リストは 50 件を上限に古いものから落とす。状態には「どこまで送ったか」の目印（最後に送った発話の終了秒 `consumedThrough`）を持たせ、次の入力の切り出しと CLI の `--state` はこれを使う。出力の言語は発話と同じ言語（プロンプトで指示。言語の設定は作らない）。
2. **周期。** 設定 `liveSummaryIntervalSeconds`（既定 20、下限 10、上限 120。利用者の要望は 10〜30 秒）。タイマーは録音開始で動き、次の条件がそろったときだけ呼ぶ: 録音中（一時停止中は呼ばない）、前回の成功以降に新しい確定発話が 1 件以上ある、呼び出しが進行中でない。呼び出しが間隔より長くかかったら、終わった直後に次の判定をする（溜めない）。停止で最後に 1 回呼ぶ（新しい発話があるときだけ）。そのために `LiveTranscriptionWiring` に「会議 ID つきの確定発話の流れ」を足し、停止時は `LiveFeed.finish()` が終わってから流れを閉じる（`LiveFeed` 自体は外に出さない。actor の持ち主は wiring のまま）。`claude auth status` などの待ちは録音イベントのリスナーの中では行わず、要約側の Task で行う。
3. **モデルと呼び方。** 設定 `liveSummaryModel`（既定 `haiku`。Claude Code の `--model` に渡す別名か ID）。引数は既存の `ClaudeCodeSummarizer.arguments` と同じ組み立てを共有する（`--strict-mcp-config`、`--mcp-config`、`--setting-sources project` を含む。利用者の hooks・MCP・CLAUDE.md を読ませない）。それに `--json-schema <schema> --model <model>` を加え、タイムアウト 60 秒、作業ディレクトリは `paths.liveSummaryWorkingDirectory`（最終議事録とは別）。結果の判定（利用制限・未ログイン・その他）は `ClaudeResultClassifier` を `MinutesOutput` 以外でも使える形にして共有する。`claude auth status` は録音開始時に 1 回だけ確認し、失敗ならその録音では要約を切る（ログ 1 行）。
4. **失敗の扱い。** claude が見つからない／未ログイン → その録音では何も出さない（ログ 1 行。準備カードが claude の不足を見せている。未ログインは画面に出ないが、それは既存の議事録経路と同じ）。利用制限（`ClaudeResultClassifier` の判定）→ 次の呼び出しまでの待ちを 2 倍ずつ伸ばす（上限 5 分）、画面に薄く「要約を休止中（Claude の利用制限）」、制限が解けたら自動で戻す。**最終議事録を優先する**: 待ち行列が利用制限の待ち（rate-limit round）に入っている間は、ライブ要約は呼ばない（同じ薄い表示）。その他の失敗 → 前回の状態を残して次の周期に再試行、3 回続けて失敗したら薄く「要約を更新できません」。
5. **表示。** 録音中の右ペイン（`RecordingDetailView`）のライブ文字起こしの**上**にカードを置く: 「いま」（太字の 1 文）、「決定事項」（箇条書き）、「宿題」（箇条書き。担当があれば末尾に「— 担当」）、右下に「n 秒前に更新」。最初の結果が来るまでカードは出さない（「準備中」も出さない）。オフのときは出さない。停止後の `ProcessingDetailView` と、議事録が作れなかった会議の `MinutesMissingView`（transcript_only / failed。利用制限で議事録が無いときはこれが唯一の要約）にも同じカードを読み取り専用で残し、議事録ができたら（`CompletedDetailView`）出さない。
6. **保存。** 更新のたびに `transcripts/<id>/live-summary.json`（`live.json` の隣。状態 + 更新時刻 + `consumedThrough`）を書く。再起動後に `ProcessingDetailView` が読めるように。manifest・minutes.json・最終議事録は変えない。
7. **設定画面。** 一般タブの Claude の設定（モデル・パス）の下に「リアルタイム要約」の節: オン/オフ（`liveSummaryEnabled`、**既定オフ**。会議中に発話テキストを Claude に送り続け、利用枠を消費するため。利用者は自分でオンにする）、更新間隔（秒。10〜120、既定 20）、モデル（既定 `haiku`）。JSON キーは snake_case（`live_summary_enabled` / `live_summary_interval_seconds` / `live_summary_model`）。間隔の変更は次の周期から効く（録音の再開始は要らない）。一般タブの外部送信の説明文（`externalNotice`）に「リアルタイム要約をオンにすると録音中も確定した発話のテキストを送る」を足す。議事録タブ（`_autonote/` のファイル編集）には置かない。
8. **プロンプト。** `DefaultPrompt.liveInstructions` に固定文を置く。出力の言語は発話と同じ言語（上の 1。言語の設定は作らない）。「推測で決定事項を作らない」「決まっていないことは宿題にも入れない」「`now` は話題を名詞中心の 1 文で」を明記する。スキーマは `--json-schema` で固定。
9. **CLI と E2E。** `autonote dev live-summary <live.json> [--state <json>] [--claude]` を足す。`dev summarize` と同じ向きで、`--claude` を付けたときだけ本物の claude を呼び、付けなければ決定的な偽の状態（発話数と `consumedThrough` から作る）を返す。E2E はこれで JSON の形と累積（2 回目の呼び出しで前回のリストと `consumedThrough` が引き継がれる）を固定する。GUI 側の周期・条件・バックオフ・停止時の最後の 1 回は `swift test`（偽の要約器 + 偽の時計。`AppModel.settle()` の `streamCount` を購読の追加に合わせて直す）で固定する。GUI の E2E は既定オフなので claude を呼ばない（E2E 13 番の方針どおり）。「カードが出ない・録音が通常どおり止まる」だけ確かめる。

## 制約

- 既存の Global Constraints（`docs/superpowers/plans/2026-10-25-autonote-plans-overview.md` §9）と §8i。Swift 6 strict concurrency、TDD、E2E は `scripts/e2e-check.sh` に追加。
- `LiveFeed` / `LiveTranscriptionWiring` / `AppModel.applyLive` の流れは変えない。要約はその購読者として足す（`LiveFeed.snapshot()` か `updates()` の確定分を読む）。
- 1 回の入力は上限を持つ（発話テキストで 8,000 文字を超えたら古い方から落とし、落とした旨を `[前略]` で示す）。

## builder check で決めたこと（2026-10-28）

- 既定オフ。外部送信の説明文を更新する。E2E も既定オフで claude を呼ばない。
- 設定は一般タブ（Claude の設定の隣）。言語の設定は作らず、発話の言語に合わせる。
- 停止時の最後の 1 回は wiring に会議 ID つきの流れを足して作る。`LiveFeed` は外に出さない。
- 最終議事録を優先する（待ち行列が利用制限の待ちにある間はライブ要約を止める）。
- 引数の組み立てと結果判定は既存の `ClaudeCodeSummarizer` / `ClaudeResultClassifier` と共有する。
- 保存先は `transcripts/<id>/live-summary.json`。`MinutesMissingView` にもカードを出す。
- CLI は `--claude` で本物、既定は偽（`dev summarize` と同じ向き）。
- 停止後のカード（処理中・議事録なし）は『n 秒前に更新』を出さない（計画 09 Task 7 の裁定）

## 作り手に任せること

- 型の名前と置き場所（例: `Minutes/Live/LiveSummarizer.swift`、`LiveSummaryState`、`LiveSummaryScheduler`、`LiveSummaryWiring`）。
- 設定画面の部品（Stepper か Slider か。間隔の表示は「20 秒」）。
- カードの見た目（`StatusHeader` の帯と同じ余白・角丸に揃える程度で、新しい色は足さない）。
- 「n 秒前に更新」の更新方法（既存の 1 秒ティックで引く。押して流さない）。
- 停止時に最後の 1 回を待つ時間の上限（60 秒のタイムアウトで打ち切り、結果が来なければ前回の状態のまま）。
- `claude auth status` の 1 回確認を `ClaudeCodeSummarizer` と共有するか別に持つか。

## 想定する負荷

20 秒間隔で発話が続く会議なら最大 180 回/時の呼び出し。1 回の入力は前回の状態（数百〜数千文字）+ 直近の発話（数百文字）だが、`claude -p` はそれに加えて Claude Code 自身のシステムプロンプト等で**1 回あたり約 1 万トークンの固定費**がかかる（builder check の指摘）。つまり 180 回/時で約 180 万トークン/時の利用枠を使う。haiku なら数秒で返る。利用枠は最終議事録と同じ枠なので、既定オフ・最終議事録の優先・自動バックオフ（上の 4・7）が必須。固定費を無くすには Claude Code を介さず API を直接呼ぶ必要があるが、本プロジェクトは API キーを持たない方針なので非ゴール。
