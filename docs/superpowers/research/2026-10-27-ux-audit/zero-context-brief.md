# ゼロコンテキスト操作テスト（被験者エージェント向け）

あなたは macOS 上で動いている、名前も用途も知らされていないアプリを、初めて触る一般ユーザーとして操作します。
アプリについての説明・README・ソースコードは一切読んではいけません（`Sources/`, `docs/`, `README.md`, `*.swift` を開いたら失格）。
画面に見えるもの（スクリーンショットとアクセシビリティツリー）だけを手掛かりに進めてください。

## 操作手段（これだけ使う）
`AX=<axtool のパス>`、`PID=<pid>` は本文末尾に与える。

- `$AX $PID dump` … 今見えているウィンドウとメニューバー項目の要素一覧（[番号] 役割 タイトル … frame=(x,y,wxh) actions）。番号は dump のたびに振り直されるので、操作の直前に必ず dump し直す。
- `$AX $PID press <番号>` … その要素を押す（ボタン・メニュー項目・チェックボックス・タブ）。
- `$AX $PID setvalue <番号> "<文字列>"` … テキストフィールドに値を入れる。
- `$AX $PID click <x> <y> [right]` … 画面座標でクリック（frame の x,y は画面座標。要素の中心を狙う）。右クリックは `right`。
- `$AX $PID key <keycode> [cmd|shift|opt|ctrl]...` … キー送信（Return=36, Escape=53, Tab=48, Delete=51, Space=49）。
- `$AX $PID shot <windowid> <保存パス.png>` … ウィンドウのスクリーンショット。windowid は `$AX $PID windows` で得る。
- `$AX $PID windows` … 今あるウィンドウの id・タイトル・位置。
- スクリーンショットは Read ツールで必ず目視すること。見た目の印象（何が押せそうに見えるか、何を意味するのか分からなかったか）が最重要の記録。

メニューバーの右上にあるこのアプリの項目は dump の「-- status items --」に出る。ここが入口。

## 課題（上から順に。各課題の制限は 25 手。超えたら「諦めた」と記録して次へ）
1. このアプリが何をするアプリか、画面だけから推測して一文で書く。
2. 今から始まる打ち合わせを記録したい。記録を始め、20 秒ほど待ってから止める。
3. 止めた後、記録の結果（まとめ・メモ・文字起こしなど）がどこで見られるか探し、見つけたら内容を 1 行引用する。見つからなければ、画面が何を伝えていたかを書く。
4. 記録の結果が保存されるフォルダを、デスクトップの `AutoNote-UX-Test` という新しいフォルダに変える。
5. 「記録開始」を素早く始めるためのキーボードショートカットが何か見つけ、書く。
6. アプリを終了する。

## 記録（最重要）
各手ごとに: 何を見て（スクショのパス）→ 何を期待して → 何を押して → 何が起きたか。
特に次を必ず書く:
- **迷った瞬間**: 複数の候補で迷った、意味が分からない語・アイコン・無効化された項目があった、次に何をすればよいか分からなかった。
- **誤操作**: 期待と違う結果になった操作。
- **安心できた点**: 迷わず進めた理由（ラベル、配置、状態表示など）。
最後に、課題ごとの「成功/失敗/諦め」「手数」「迷った回数」と、全体の所感（説明書なしで使えるアプリか 5 段階）を書く。
