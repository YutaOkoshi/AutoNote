# AutoNote UI 監査（2026-10-27）— 説明文なしで初見操作できるか

対象: ブランチ plan-06、HEAD c4ab487（監査中に見つけた P0 を修正した版）。macOS 26、ダーク外観、隔離データ領域（`AUTONOTE_DATA_DIR`）で初回起動。

## 方法
1. **ベストプラクティスの収集**: Apple HIG（メニューバーエクストラ・メニュー・アラート・権限・オンボーディング・設定・進捗・通知）、Nielsen の 10 ヒューリスティクス、NN/g の空状態・段階的開示・シグニファイア、競合（Granola / MacWhisper / Audio Hijack / Krisp）から、画面で判定できる 61 項目に落とした → [checklist.md](checklist.md)
2. **全画面の撮影と採点**: 同意・メニュー・メイン（初期/完了/録音中/停止後）・取り込み・削除確認・設定 8 タブを自前の AX ツールで撮影し、61 項目を採点 → [scorecard.md](scorecard.md)、[shots/](shots/)
3. **ゼロコンテキスト操作テスト**: アプリの説明を一切与えないエージェントに [同じブリーフ](zero-context-brief.md) で 6 課題を与え、迷った瞬間を記録させた → [tester-1-sonnet.md](tester-1-sonnet.md)、[tester-2-opus.md](tester-2-opus.md)

Orca の computer-use はこのアプリの SwiftUI ウィンドウを読めなかった（後述の P0 が原因で AX が応答しなかった）ため、AXUIElement + ScreenCaptureKit の小さなツールを scratchpad に作って操作・撮影した。

## 結論
**「説明文が要らない」水準にはまだ届いていない。** 録音の開始・停止・終了はメニューバーだけで迷わず、ゼロ知識の被験者も 6 課題中 5 課題を完遂した。しかし **初回起動から議事録を手にするまで** の導線が切れている。被験者の自己評価は 5 段階で 3.5。

## P0: 監査中に見つけた不具合（修正済み c4ab487）
録音開始の瞬間から主スレッドが 100 % で回り、ウィンドウが再描画されず、アクセシビリティも SIGTERM も効かなくなっていた。原因はメニューバーラベルの `TimelineView(.periodic)` が MenuBarExtra の中で SwiftUI の更新を抜けられないこと。`AppModel` が毎秒刻む `elapsedSeconds` で描くように変更し、E2E 06.7（録音開始 3 秒後の CPU とメニューバー項目の読み取り）を追加。窓を閉じていても再現したので、計画 06 の実機確認では気づけない種類の不具合だった。

## 良かった点（維持する）
- メニュー構成（録音開始／ウィンドウを開く／設定…／終了）は HIG どおりで、被験者 2 名とも迷わなかった。
- 録音中のヘッダ「● 録音中 0:18」とメニューバーの経過時間、停止後の「文字起こしする／破棄」の帯。
- 削除確認: タイトルが具体的、消えるものを列挙、赤い「削除」、キャンセルあり。
- 画面内の補足文（出力フォルダの説明、保持日数の説明、ショートカットの修飾キー説明）は的確。
